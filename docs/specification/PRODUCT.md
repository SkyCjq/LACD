# LACD 产品规格：独立产品目标、非目标、术语（v1.0 冻结版）

> 状态：FROZEN（2026-10-12）。后续变更须经 ADR 并经 Human 批准。

## 1. 产品一句话

LACD（Lightweight Agentic Collaborative Development，轻量智协开发）是一个
**完全独立、通用、业务无关**的 Agentic 软件开发治理与协作框架：
它定义软件项目如何组织 Agent 工作、验证证据、控制变更风险、治理 GitHub
变更，以及如何以受控方式持续采用 LACD 新版本。

## 2. 产品目标（Goals）

1. **独立可安装**：从可验证的源码、固定 tag/commit 或版本化发行包安装，
   不依赖任何业务项目。
2. **可重复接入**：`lacd init` 对新仓库与已有仓库安全、幂等、冲突可见、可预览。
3. **机器可确认的采用状态**：`lacd status --json` / `lacd verify` 明确区分
   声明（declared）、本地有效（validated）、远端实际强制（enforced）与
   未验证（unverified）。
4. **可执行的开发治理**：Agent 协议、风险分级（T0/T1/T2）、PR/CI 流程、
   GitHub 原生保护集成、可验证证据（绑定 commit SHA）。
5. **可持续的版本化升级**：版本锁定 → 发现新版 → 兼容性检查 → 差异预览 →
   生成升级分支/PR → 自动测试 → Human 审查合并 → 升级后验证，
   且项目自定义规则不丢失。**这是 v1.0 强制功能。**

## 3. 非目标（Non-goals，v1.0 明确不做）

- 不是业务脚手架：不生成业务代码、数据模型、领域规则。
- 不是中央 SaaS：不建强制在线的中央服务器、登记数据库，不收集用户令牌。
- 不是包管理器：不替代 pip/npm；只锁定 LACD 自身版本与受管模板。
- v1.0 不做：签名基础设施（预留字段，不伪称已验证）、自动合并、
  跨项目集中监控（未来可选功能）。

## 4. 独立性铁律（最高架构约束）

1. LACD 主仓库不得包含任何特定业务项目的名称、业务数据模型、数据源、
   路径、专属规则、品牌标识、真实凭证或运行依赖。
2. LACD 不得要求使用者复制另一业务仓库；不得把任何既有业务流程
   默认当作 LACD 标准。
3. 通用功能必须在**两个或更多全新、相互独立的合成测试仓库**中证明可用。
4. 项目可维护附加治理规则，但不得静默削弱 LACD 基础安全契约。
5. 业务项目是 LACD 的**采用者（adopter）**，不是子模块、设计来源或依赖项。
6. 真实业务项目如后续成为采用者，在**其自身仓库**另行执行接入与
   升级 PR；LACD 主仓库不得出现任何采用者的专用实现、Profile、Fixture、
   测试或文档示例（独立性铁律，见 ADR-0011）。

**核心原则：LACD 发布并演进一套通用框架；采用项目只选择何时以受控 PR
升级至新版本，无需在两边重复开发或手动复制代码。**

## 5. 术语表

| 术语 | 定义 |
|---|---|
| 采用者（Adopter） | 使用 LACD 的业务项目仓库 |
| 受管内容（Managed content） | LACD 生成、由锁文件记录 hash 的内容（模板、工作流） |
| 项目内容（Project-owned） | 用户维护的业务代码、手写规则、CI、指令；升级永不触碰 |
| 共享内容（Shared content） | 如 AGENTS.md：LACD 管理标记 section，用户拥有其余部分 |
| 版本锁（Lock） | `.lacd/lock.json`：精确版本、来源、hash 的机器可读记录 |
| 模板包（Template bundle） | 某版本 LACD 的受管模板集合，发布时带 sha256 摘要 |
| 三方比较 | 旧版上游基线（锁中 hash）+ 当前项目内容 + 新版上游目标 |
| 证据（Evidence） | 绑定 commit SHA 的测试/审查结论；HEAD 更新后旧证据失效 |
| 风险分级 | T0 文档类 / T1 常规代码 / T2 安全敏感（路径+语义，取最高；未知从严） |

## 6. 版本线

- LACD 自身遵循 SemVer（见 UPGRADE_CONTRACT.md）。
- 五类版本**彼此独立**：CLI/发行包版本、配置 Schema 版本、治理策略版本、
  模板版本、锁格式版本。`status --json` 的 `versions` 字段同时报告五者；
  兼容性关系见 UPGRADE_CONTRACT.md §3。
